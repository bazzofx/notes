### Planning for Windows hosts Security Events Connector
There are  two Windows security events Content Hub solution options to stream events from Windows devices to Microsoft Sentine

![[Pasted image 20260711195205.png]]
The first option is to install the _Windows Security Events_ Content Hub solution. You can choose either of the two agent data connectors available:
- Windows Security Events via AMA Connector
- Security Events via Legacy Agent Connector


#### 2nd Option Windows Forwarded Events Content Hub
![[Pasted image 20260711194813.png]]
The second option is to install the Windows Forwarded Events solution from Content Hub, then set up a Windows Event Collector device to receive logs from Windows machines and forward them to Sentinel via the Windows Forwarded Events data connector

### Windows Security Events: AMA vs. Legacy Agent
The Windows Security Events via AMA Connector has the following differences from the Security Events via Legacy Agent Connector:
Benefits:
- Manage collection settings at scale
- Azure Monitoring Agent shared with other solutions
- Performance improvements
- Security improvements
Requirements:
- **non-Azure VM's/devices require Azure Arc.**

### Connect using the Windows Security Events via AMA Connector
The Windows Security Events via Azure Monitor Agent (AMA) Connector uses Data Collection Rules (DCRs) to define per-agent data collection, offering two key advantages.
- DCRs enable scalable collection management with scoped, per-subset configurations. They are workspace and VM independent, allowing reuse across machines and environments.
- AMA uses custom filters to ingest only targeted events, applying rules at the source and excluding everything else

**Prerequisites**
- Read/Write permissions on Ms Sentinel Workspace
- To collect system that isn't an Azure VM, system must have **Azure Arc** installed + enabled before enabling Azure Monitor Agent-based connector
These include:
- Windows servers installed on physical machines
- Windows servers installed on on-premises virtual machines
- Windows servers installed on virtual machines in non-Azure clouds

### Connect using the Security Events via Legacy Agent Connector

**This is showing to be going EoL** [link on AMA End of Life](https://techcommunity.microsoft.com/blog/microsoftsentinelblog/what-to-do-if-your-sentinel-data-connector-shows-as-deprecated/4270346)

The Windows Security Events via AMA connector streams security events from Windows machines to Sentinel, enabling dashboards, alerts, and investigations. It offers four event collection options:

- All Security Events – All Windows security and AppLocker events.
- Common – A balanced set for auditing, including full user sign-in/out trails and key security actions. Designed to reduce volume while maintaining audit completeness.
- Minimal – A focused set for potential threats, excluding high-volume, low-signal events like sign-outs. Covers sign-ins, failures, and process creation.
- Custom – Use XPath queries to specify or filter specific logs.

### Connect Azure Windows Virtual Machines

1. Go to **Data connectors** and select **Windows Security Events via AMA**.
2. Click **Open connector page**.
3. Confirm you have the required permissions (see Prerequisites).
4. In **Configuration**, click **+Create data collection rule**.
5. Enter a **Rule name**, choose **Subscription** and **Resource group**, then click **Next: Resources**.
6. Under **Scope**, expand your subscription and resource group, then select your Azure VMs.
7. Click **Next: Collect**, review the event collection options (default is **Keep All Security Events**), then click **Next: Review + create**.
8. Click **Create**, wait a moment, then **Refresh** to see the new rule listed.

### Connect non-Azure Windows Machines

1. Go to **Data connectors** and select **Windows Security Events via AMA**.
2. Click **Open connector page**.
3. Confirm you have the required permissions (see Prerequisites).
4. In **Configuration**, click the pencil icon to edit the existing data collection rule.
5. Under **Scope**, expand your subscription and resource group to view resources.
6. Click **Next: Collect**, review the event collection options (default is **Keep All Security Events**), then click **Next: Review + create**.
7. Click **Create**, wait a moment, then **Refresh** to see the updated rule.
>[NOTE]
>If you don't see any non-Azure Windows machines, open _Azure Arc_ to verify the machines are connected to Azure Arc.

### Collect Sysmon event logs
#### Install the SysMon add-on on Sentinel
To collect SysMon logs on Sentinel, we need to install the solution

1. For Microsoft Sentinel in the Azure portal, under **Content management**, select **Content hub**. For Microsoft Sentinel in the Defender portal, select **Microsoft Sentinel** > **Content management** > **Content hub**.
2. Search for and select **Windows Forwarded Events**.
3. On the details pane, select **Install**.
#### Configure SysMon Data Collector
**To set up the Windows Forwarded Events data connector:**

1. In Microsoft Sentinel, go to **Configuration** > **Data connectors**.
2. Select **Windows Forwarded Events** and click **+Create data collection rule**.

**Basic tab fields:**

|Field|Description|
|---|---|
|Rule Name|Descriptive name to identify the DCR|
|Subscription|Subscription to store the DCR (can differ from VMs)|
|Resource group|Resource group to store the DCR (can differ from VMs)|
3. Click **Next: Resources**.
4. Under **Scope**, expand your subscription and resource groups, then select the VMs to connect.
5. Click **Next: Collect**, select the **Custom** radio button.
6. Enter an XPath query (e.g., `Microsoft-Windows-Sysmon/Operational!*` for Sysmon events) and click **Add**.
7. Click **Next: Review + create**, validate, then click **Create**. ![[Pasted image 20260711204357.png]]![[Pasted image 20260711204347.png]]
8. After the DCR is created, select the **Refresh** button to see the rule. You can also edit or delete existing rules from the **Configuration** section of the connector page.
This connector can use the Advanced Security Information Model (ASIM). Microsoft recommends that you use the ASIM normalization. For more information on ASIM, see [Advanced Security Information Model (ASIM)](https://learn.microsoft.com/en-us/azure/sentinel/normalization).

9. On the **Windows Forwarded Events** connector page, **Configuration** section, select the **Deploy** button.
    
10. Fill-in the required fields of the **Custom deployment** ARM template, and select **Review + create**.
    
11. When validation passes, select **Create**.
